# Нагрузочное тестирование

Сценарии k6 — в [../k6/](../k6/), отчёты прогонов складываются в [../k6/results/](../k6/results/). Целевые числа и их происхождение — в [design.md](design.md), раздел 6: 1000 записей/с, около 10 000 чтений/с, рейтинг до 10 млн игроков.

## Стенд

Apple M2 Pro (12 ядер: 8 производительных и 4 энергоэффективных), 16 ГБ, macOS 26.6.2. Docker Desktop, Engine 27.4.0, VM `NCPU=12`, `MemTotal` 7.65 ГиБ. Node v22.12.0. PostgreSQL и Redis в контейнерах, API и воркер — нативные процессы, генератор `grafana/k6:0.54.0` в Docker **на том же хосте**, поэтому генератор и сервис делят процессор. Характеристики хоста и Docker VM на момент конкретного прогона `k6/run-all.sh` пишет в заголовок каждого txt-отчёта.

## Как повторить

1. Поднять хранилища, API и воркер (`docker compose up --build` или нативно, см. [README](../README.md)).
2. Залить игроков: `npm run seed -- --players 1000000`. Seed заканчивается пересборкой рейтинга.
3. Запустить все три сценария:

```bash
PLAYERS=1000000 k6/run-all.sh
```

Скрипт по очереди прогоняет `write`, `read` и `mixed` и для каждого сохраняет в `k6/results/`:

| Файл | Содержимое |
|---|---|
| `<сценарий>-<PLAYERS>.txt` | параметры прогона (время, коммит, все переменные, хост, ресурсы Docker VM), затем вывод k6 |
| `<сценарий>-<PLAYERS>.json` | сводка k6 (`--summary-export`) |
| `<сценарий>-<PLAYERS>-lag.txt` | `outbox_backlog` и `outbox_lag_seconds` воркера каждые 4 с |

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PLAYERS` | `100000` | диапазон id `p000000001…`; не больше числа игроков в seed |
| `DURATION` | `30s` | длительность каждого сценария |
| `WRITE_RATE` | `1000` | записей/с в `write` и `mixed`; в `mixed` чтения идут по `5 × WRITE_RATE` на top и на rank |
| `READ_RATE` | `10000` | чтений/с в `read`, поровну на top и rank |
| `MAX_VUS` | по умолчанию сценария | потолок виртуальных пользователей на сценарий |
| `BASE_URL` | `http://host.docker.internal:3000` | адрес API из контейнера k6; несколько адресов через запятую — нагрузка на несколько инстансов |
| `METRICS_URL` | `http://localhost:9100/metrics` | метрики воркера для снятия лага |

Отдельный сценарий можно запустить и через npm: `PLAYERS=1000000 DURATION=60s npm run k6:mixed` — скрипты пробрасывают `PLAYERS`, `DURATION`, `RATE`, `WRITE_RATE` и `MAX_VUS`, но отчёты не сохраняют.

## Как читать цифры

При `constant-arrival-rate` k6 запускает итерации с заданной частотой, и если свободных виртуальных пользователей нет, итерация **отбрасывается** (`dropped_iterations`) и в задержки не попадает. Поэтому заметный dropped означает, что целевая нагрузка не достигнута, а p95 и p99 занижены — самые медленные моменты частично не измерены. Сравнивать между собой стоит только прогоны с одинаковыми `MAX_VUS`, `PLAYERS` и числом инстансов API на одной машине.
