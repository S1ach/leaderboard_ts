## Повторная проверка дефектов

**SMOKE-01 — рассинхронизация PostgreSQL/Redis при конкуренции: проверка исправления PASS.** Базовый сценарий из 20 одновременных +1 прошёл. Дополнительно выполнено 10 независимых серий по 100 одновременных +1 одному новому игроку в каждой серии. В каждой серии ответы POST содержат ровно результаты 1…100, итог в PostgreSQL равен 100, rank через Redis также равен 100. Выполнен и новый существующий regression-тест `test/concurrency-order.test.ts`. Повторные HTTP-серии повышают уверенность в исправлении, но не являются исчерпывающей проверкой всех порядков выполнения транзакций.

**SMOKE-02 — rank отклонял допустимый player_id: проверка исправления PASS.**

| ID | POST /score | GET /leaderboard/rank/{id} |
|---|---|---|
| 100 ASCII-символов | 200 | 200 |
| 101 ASCII-символ | 200 | 200 |
| 128 ASCII-символов | 200 | 200 |
| 129 ASCII-символов | 400 | 400 |
| `игрок /?#😀` (URL-encoded) | 200 | 200 |

Для успешных GET сверялись идентификатор и счёт из предшествующего POST, а не только HTTP-код.

Конкурентный скрипт использует новые ID для каждого запуска и сверяет оба хранилища. Интеграционные тесты используют отдельную БД `leaderboard_test` и Redis DB 1.
